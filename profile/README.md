## Four Beats

1. **Name the model.** Give the Dlubal RFEM session a short title before you edit members or surfaces.
2. **Pin the live mesh.** Keep current members, surfaces, and loads on the Dlubal RFEM board and leave unused cases aside.
3. **Check the combination.** Read the Dlubal RFEM summary of the governing case before you treat a diagram as final.
4. **Close the loop.** Note which result diagrams are ready so the next Dlubal RFEM visit does not start by hunting the mesh.

## Field Note

Dlubal RFEM is easier to trust when the mesh stays smaller than the building it came from. A named session shows which frame is active, the pins show which members and surfaces you will read today, and the closing note tells the next person which load combination drives the result diagrams. That record is short on purpose: not a copy of every element, only the path back to the model that is still open.

The same loop fits a student frame, a client floor plate, or a computer shared by two engineers. Open the last Dlubal RFEM session, confirm one combination, and leave the governing diagram easier to find than you found it. Drawings stay where they are. Dlubal RFEM only holds the member and surface mesh, the summary, and the handoff.

## One Real Pass

Pick a model that already has a name: a portal frame, a floor surface, or a small building core. Open it in Dlubal RFEM, keep only those members and surfaces on the board, and read one result diagram you can point to. A pass is done when that diagram is tied to a load combination and the unused cases are no longer in the way. Dlubal RFEM does not need a full rebuild of the structure before it is useful.

If the pass feels crowded, the mesh is too wide. Drop anything that belongs to a different load path and leave it out of this workspace. The next pass can have its own title. What matters is that this one stays readable from the first member to the last surface, with the summary still matching the result diagrams on the board.
